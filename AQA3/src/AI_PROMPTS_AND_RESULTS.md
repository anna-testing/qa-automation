# Сохранённые промпты и результаты

## Задание 1 — генерация Page Object

**Промпт**

> Сгенерируй Java 21 класс LoginPage с использованием Page Object и Selenide. На странице SauceDemo есть username с id `user-name`, password с id `password`, кнопка Login с классом `submit-button`, сообщение ошибки с `data-test="error"`. Добавь методы открытия страницы, логина и проверки точного текста ошибки. Используй читаемые имена и Selenide `should`.

**Результат и решение по ревью**

AI предложил отдельные методы `openPage`, `loginAs` и `shouldShowError`. В итог взята структура методов, но локатор кнопки изменён с менее устойчивого `.submit-button` на уникальный `#login-button`; проверки дополнены пояснениями `because`.

## Задание 3 — первый короткий промпт

**Промпт**

> Напиши Gherkin-сценарий на русском языке для проверки успешной авторизации на сайте saucedemo.com. Используй ключевые слова: Допустим, Когда, И, Тогда.

**Черновой результат — manual-solution**

```gherkin
Функционал: Авторизация
  Сценарий: Успешный вход
    Допустим пользователь находится на сайте
    Когда пользователь вводит правильные данные
    И нажимает кнопку входа
    Тогда открывается главная страница
```

Недостатки: «правильные данные» и «главная страница» не определены, а шаги трудно связать с параметризованными Step Definitions.

## Задание 3 — уточнённый промпт

**Промпт**

> Напиши Gherkin-сценарии на русском языке для SauceDemo. Страница входа открывается по `/`; пользователь вводит `standard_user` в `user-name`, `secret_sauce` в `password`, нажимает Login и должен увидеть заголовок `Products`. Добавь негативную авторизацию таблицей примеров. Описывай поведение, не CSS-селекторы; используй параметризуемые шаги, `Предыстория` и `Структура сценария`.

**Результат — ai-assisted-solution**

После ревью сформирован исполняемый файл `test/resources/features/saucedemo.feature`: общая предыстория, позитивная покупка, два примера неверной авторизации, проверка обязательных полей и отдельный диагностический сценарий.

## Задание 4 — анализ Allure

**Промпт**

> Проанализируй stack trace `Element not found {[data-test='error']}` после успешного шага входа и скриншот страницы Products. Объясни, почему упал UI-тест, отдели дефект приложения от ошибки теста и предложи минимальное исправление. Учти, что сценарий помечен `@diagnostic` и создан намеренно.

**Ответ AI**

AI классифицировал падение как ошибку теста: проверка сообщения авторизации выполняется уже на странице каталога, где `[data-test='error']` отсутствует. Рекомендация — убрать неверный шаг либо проверять реальный элемент каталога, а диагностический сценарий исключить из регресса. Вывод совпадает с реальной причиной.
